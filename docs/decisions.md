# Архитектурные решения

Проект исследует Conan как каталог аппаратных проектов с точными зависимостями.
Публичная модель отражает возможности Conan: Record и Dependency.
Операции dependencies и find_dependents заменяют общий направленный поиск соседей.
Реализация хранилища одна — Conan. Тесты используют временные cache
и собственный локальный сервер. Catalog предоставляет короткие публичные методы
и управляет клиентом Conan. Операции чтения, публикации, разрешения графа и получения
файлов вынесены в функции `_internal/conan`; протокола Backend, отдельных адаптеров,
CatalogGraph, слоёв Reader и транзакционного чтения нет.
Единственная точка разрешения графа —
resolve_local: она получает локальное описание без проверки публикации корня.
Описание уже сохранённого пакета можно получить через get и dependencies
и передать тому же resolver.

Представление определяется координатами namespace/name/kind. Чтобы найти LIB/LEF
для заданного RTL, приложение задаёт фильтры кандидатов и проверяет наличие точного
RTL в их графах. Промежуточные узлы могут относиться к любым компонентам.

Версии представлений независимы. Данные опубликованного Ref неизменяемы; повторная
публикация запрещена. Исходящие зависимости сохраняются вместе с новым узлом.
Conan выполняет разрешение своего графа и фиксирует версии/revisions lockfile.
Алгоритм совместимости графового каталога и типизированные рёбра удалены.

Граф загружается как нативный объект Conan API и использует его зависимости и
топологическую сортировку. Доступ к version-specific объектам изолирован и закреплён
на Conan 2.34.x. Все команды выполняются через Command API. Формат рецепта
канонический, без settings/options, overrides и диапазонов. Record сериализуется
в JSON; имя Python-класса пользователя и пользовательские декодеры не хранятся.
Git source хранится в SCM-метаданных Conan; код остаётся в GitLab и получается
через tools.build:download_source=True при materialize(with_sources=True).
В binaries копируются только обычные файлы. LocatedResource остаётся внешним путём.

Lockfile принадлежит проекту: хранится в RTL-репозитории или BE workspace и явно
передаётся Conan при публикации и разрешении графа. Каталог не
парсит, не сериализует и не проверяет JSON-схему lockfile. Создание и обновление
делегированы штатным командам Conan. Materialize получает опубликованный пакет
по точной revision и закреплённым requirements, без проектного lockfile.
Рецепты используют один текущий формат: точные recipe revisions прямых
зависимостей находятся в requirements, проектный lockfile не экспортируется.
Совместимость с прежними шаблонами не поддерживается. SCM-код получается отдельно
через `source()`; `exports_sources` не используется. Обычные файлы
артефактов экспортируются вместе с рецептом и копируются в `package()`.
Пользователь передаёт JSON, а рецепт и нативный граф остаются внутренними объектами.

При настроенном remote сервер Conan определяет наличие опубликованных записей.
Локальный cache используется для работы Conan: получения рецептов и файлов,
разрешения графа и создания пакетов. Подготовка использует выбранный cache напрямую,
без копирования home и переноса через cache save/restore. Один publish создаёт
один пакет с уже опубликованными зависимостями. Conan export-pkg сам выполняет
экспорт рецепта, разрешение графа и упаковку файлов. Затем пакет загружается через
upload. Batch-подготовки, её топологической сортировки и отдельной проверки DAG нет.
Сбой может оставить рецепт или пакет в cache; автоматического rollback нет.

Прямой обратный поиск читает requirements кандидатов; транзитивный загружает
нативный граф каждого кандидата. Отдельного индекса обратных связей нет.
Установка использует один install без предварительных graph info и команд lock.
Посторонний lockfile из текущей директории явно отключён.
Пагинация, автоматические повторы, миграции
старых форматов и управление конкурентными издателями не реализованы.

Conan home, профили и remotes настраивает вызывающее приложение или пользователь.
SDK не создаёт собственных профилей. Единственный включённый remote выбирается
автоматически; несколько требуют явного имени, отсутствие remotes разрешает
работу с локальным cache.

# Структуры данных

## Ссылка на объект: Ref

`Ref` задаёт точную идентичность вершины графа. Все поля обязательны
и должны быть непустыми строками.

| Поле | Назначение |
|---|---|
| `namespace` | Пользовательская область имён: команда, группа проектов или другая область |
| `name` | Имя объекта внутри области имён |
| `version` | Точная версия объекта или идентификатор конкретного запуска |
| `kind` | Пользовательский вид объекта |

Идентичность включает все четыре поля. Одинаковые имя и версия в разных namespace
или с разными kind обозначают разные объекты. Семейство версий для разрешения
совместимости определяется сочетанием namespace, имени и kind.

В Memory/Memgraph формат namespace и строк версий задаёт пользователь; Conan требует [форматируемые координаты](conan.md). Каталог не разбирает namespace
и не сравнивает номера версий. Произвольных метаданных в Ref нет.

Значения kind полностью определяет пользователь: можно передать строку или значение
собственного `StrEnum`. Встроенного набора видов и регистрации нет.
При чтении kind представлен обычной строкой.

## Запись: Record

| Поле | Назначение |
|---|---|
| `ref` | Точная ссылка на объект |
| `payload` | Пользовательское содержимое; по умолчанию отсутствует (`None`) |

Релиз проекта и запуск flow представлены одним типом Record. Их различает kind;
схему ресурсов, метаданных, параметров запуска и результатов определяет пользователь.
Kind сам по себе не ограничивает допустимые виды связей.

Payload принимает JSON-значение или объект с интерфейсом
[`JSONSerializable`](interfaces.md#сериализация-пользовательского-содержимого).
Допустимы объекты, массивы, строки, числа, логические значения и null.
NaN и Infinity не сохраняются.

При публикации создаётся независимый JSON-снимок. Изменение исходного объекта
после публикации не меняет каталог. При чтении JSON-объекты представлены неизменяемыми
отображениями, массивы — кортежами. Пользователь сам восстанавливает свои классы
и проверяет схему содержимого; каталог не хранит имя Python-класса payload.

Ref и Record — неизменяемые модели. До публикации сам пользовательский payload
может оставаться изменяемым. Record предоставляет `to_json()` и `from_json()`;
представление записи состоит из ref и payload.

## Связь: Relation

| Поле | Назначение |
|---|---|
| `source`, `target` | Точные ссылки на источник и цель |
| `kind` | Вид связи из `RelationKind` |
| `alias` | Необязательное имя привязки зависимости или результата |
| `ordinal` | Необязательный неотрицательный порядковый номер привязки |
| `metadata` | Пользовательские JSON-метаданные связи |

Между двумя вершинами могут существовать несколько разных связей. Alias, ordinal
и metadata позволяют различать привязки. Полные дубликаты при публикации запрещены;
повтор непустого alias у одного источника и вида связи требует разных явных ordinal.
Relation также предоставляет `to_json()` и `from_json()`.

| Вид связи | Направление и смысл |
|---|---|
| `REQUIRES` | Объект → непосредственная зависимость |
| `IMPLEMENTS` | Реализация → реализуемый объект |
| `USED` | Запуск → использованный объект |
| `PRODUCED` | Запуск → созданный объект |
| `BACKWARD_COMPATIBLE_WITH` | Версия → предыдущая версия, которую она может заменить |

Исходящие связи публикуются вместе с новым источником и затем не дописываются.
Концы должны существовать или публиковаться в том же пакете. PRODUCED требует
новую целевую запись и допускает не более одного производителя.

Совместимость связывает версии одного семейства. У каждой версии может быть
только одно исходящее ребро совместимости; совместимость транзитивна.
Правила циклов и разрешения описаны в [архитектурных решениях](decisions.md).

## Запрос и результаты чтения

| Структура | Содержимое и назначение |
|---|---|
| `SearchQuery` | Необязательные точные фильтры name, version, kind и namespace; заданные поля объединяются через AND |
| `Neighbor` | Связь relation и запись соседней вершины record |
| `GraphResult` | Кортежи records и relations, а также признак согласованности consistency |

Пустой SearchQuery находит все записи. Поиска по payload нет.

GraphResult включает корень обхода. Результаты графовых обходов упорядочены
детерминированно: записи по идентичности, связи по JSON-представлению.
Consistency различает `snapshot` и `live`; Memory/Memgraph возвращают `snapshot`, Conan — `live`. Lockfile фиксирует зависимости, но не создаёт транзакцию remote.

`GraphResult.to_networkx()` создаёт независимый изменяемый `MultiDiGraph`.
Ключи вершин — Ref, атрибут record содержит запись. Атрибут relation у ребра
содержит связь; параллельные связи сохраняются. Изменение экспортированного графа
не меняет каталог или исходный GraphResult.

## Необязательные описания ресурсов

Ресурсы — вспомогательные инструменты пользователя. Каталог не требует их присутствия
в payload и не восстанавливает их автоматически.

| Структура | Назначение |
|---|---|
| `Resource` | Общий абстрактный интерфейс материализации ресурса |
| `GitResource` | URL репозитория, исходная Git-ссылка requested_ref и точный resolved_commit; provider — git |
| `LocatedResource` | Путь locator к ресурсу в файловой системе и провайдер; необязательные digest, size, media_type и attributes |
| `MaterializedResource` | Единственное поле path — локальный путь к содержимому |

Для Git path указывает на корень репозитория. Ресурс файловой системы описывается
абсолютным путём к доступному процессу файлу или каталогу. Подробнее —
в [интерфейсе материализации](interfaces.md#материализация-ресурсов).

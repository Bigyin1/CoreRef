# Структуры данных

Ref — пять обязательных строк namespace/component/view/type/version и необязательный
subcomponent и revision (по умолчанию None). Conan-имя имеет формат
namespace.component[_subcomponent].view.type/version[#revision]. Например,
soc.mmu.rtl.default/1.0 и soc.mmu_tlb.be.lib-lef/4.0. Все координаты входят в identity,
равенство, хеш и сортировку. При сериализации отсутствующий subcomponent опускается.
Первый `_` в сегменте компонента — разделитель; в самом component `_` запрещён,
в subcomponent разрешён (например, cluster_0). Пустой suffix недопустим.
Результат BE для части может зависеть от полного RTL-компонента.
View и type — пользовательские строки; SDK не ограничивает их словарь.
Старые name/kind и трёхчастное имя не поддерживаются.

LocalRecord описывает рабочие данные: ref, payload, source, files.
Source — Path текущего checkout, files — именованные пути упаковываемых файлов.
Внешние ресурсы, включая NFS-пути, описываются в пользовательском payload.
Flow формирует этот объект до публикации
и передаёт в Graph. Локальный корень не должен извлекаться из Conan.

Record — метаданные реестра: ref, payload, file_names и has_source.
Путей files/source в нём нет; чтение метаданных не получает бинарные файлы.
InstalledRecord наследует Record и добавляет files и необязательный source.
Все объявленные файлы уже доступны в Conan cache. Исходники получают отдельно:
has_source=True/source=None означает, что они ещё не запрошены; sources_ready
истинен после получения либо при отсутствии SCM.

Record и InstalledRecord — обычные классы со свойствами только для чтения,
без PostInit и object.__setattr__. InstalledRecord принимает готовый Record и
использует его неизменяемый payload повторно. Равенство и хеш основаны на метаданных;
физические пути и различие типа не меняют идентичность пакета.

LocalRecord.to_json() готовит format=7/ref/payload/имена files. После копирования
файлов LocalRecipe записывает SHA-256 в file_digests. Артефакты не экспортируются
в рецепт, а копируются package() из временной source_folder в бинарный пакет.
Хеши сохраняют зависимость RREV от содержимого; пути издателя не экспортируются.
Record.to_dict() выдаёт метаданные, InstalledRecord.to_dict() добавляет пути.
Record.from_json() восстанавливает соответствующий вид inspection-снимка.

Payload — произвольное JSON-значение или пользовательский JSONSerializable с to_json().
Тип JSON и протокол JSONSerializable импортируются из hwcatalog.api.records
вместе с классами записей.
При чтении и подготовке публикации он становится независимым immutable-снимком:
объекты — frozendict, массивы — tuple. Классы потребителя не сохраняются; NaN/Infinity
отклоняются. Сериализация payload остаётся ответственностью потребителя. SDK не интерпретирует
и не проверяет внешние пути из payload; их обработку выполняет flow.

SearchQuery объединяет точные AND-фильтры семи координат, построение Conan-шаблона
и фильтрацию/сортировку локальных и опубликованных записей через select(records). Dependency(source, target)
не имеет типа и дополнительных свойств. Graph содержит локальный корень,
опубликованные зависимости и точные рёбра. networkx лениво создаёт один DiGraph
с Ref-ключами без дублирования записей и зависимостей в атрибутах.
Его структура заморожена; изменяемую рабочую копию получают через networkx.copy().
ordered_refs(root, stop_at=()) и ordered_records(root, stop_at=()) возвращают
достижимую часть графа с зависимостями перед потребителями; stop_at превращает
выбранные узлы в листья. Общие зависимости других ветвей сохраняются. Порядок
для одинаковых параметров кэшируется в пределах Graph.

Dependency — frozen dataclass значений. Ref — обычный класс
с публичными координатами только для чтения. Аргумент catalog сохраняется только
в _catalog; InitVar и второго поля catalog нет. Контекст не входит в равенство,
хеш, repr и сериализацию. Новый Ref с изменёнными координатами создают через
конструктор с явным catalog.
Graph хранит записи и связи вместе с операциями над разрешённым проектом.
LocalRecord изменяем: flow может редактировать описание проекта.
Graph хранит готовый снимок; для новых входов создают новый Graph.
При publish() и создании Graph SDK отделяет payload, files, Ref и зависимости от входов;
пользовательский to_json() вызывается один раз за операцию.
Внутренний LocalRecord корня не выдаётся наружу: record, records и ordered_records()
возвращают его независимые копии. Изменение такой копии не меняет Graph или другие результаты.
Публичные поля структуры Graph доступны только для чтения; lockfile обновляет
create_lockfile() после успешного сохранения. Payload снимков рекурсивно заморожен.
Catalog и Graph — обычные классы с операциями и контекстом. Graph отвечает за одно
описание проекта и его lockfile; несколько Graph могут работать в одной директории.

Поиск по component включает целый компонент и все его subcomponent. None в фильтре
subcomponent означает отсутствие ограничения; строка задаёт точную часть. Для одного
запроса Conan используется широкий шаблон cpu*, затем matches_ref исключает соседние
компоненты вроде cpu-extra до скачивания их рецептов. Для конкретной части шаблон
становится cpu_alu. matches(record) и select(records) сохраняют точную AND-семантику.


Формат пакета 7 хранит маркер format в record.json. Это версия нашего формата записи,
не версия Conan. hwcatalog.json больше не создаётся. В conandata.yml.requires находится
единственный список прямых зависимостей с revisions; метод requirements() передаёт
его Conan через self.requires(). SCM-координаты Conan дописывает в conandata.yml.scm,
сохраняя requires. Наличие scm определяет, есть ли Git-исходники. Флага has_source
в файлах нет. StoredRecipe читает эти данные один раз за операцию, без исполнения
рецепта и без дополнительного graph info. Старый формат пакетов не поддерживается.

## Recipe revisions

Ref.revision — конкретный RREV, а None означает незакреплённый выбор. Получение пакета
превращает его в точный Ref. without_revision() снимает закрепление, сохраняя каталог.
Revision входит в identity и inspection JSON; её сортировка стабильна, но не хронологична.
Собственная revision отсутствует в переносимом record.json, потому что содержимое этого
файла участвует в вычислении RREV. StoredRecipe добавляет её из загруженной ссылки.
Локальный корень Graph или publish должен иметь revision=None; зависимости могут быть
закреплёнными или разрешаться Conan с учётом проектного lockfile. Graph.requirements,
опубликованные записи и концы рёбер содержат выбранные revisions.


Ref(reference, *, catalog) принимает каноническую строку; Ref.from_fields создаёт ссылку
из отдельных координат через тот же конструктор. Основной конструктор выполняет разбор
и проверку формата без Conan-вызовов.
Graph.info(ref) и Graph.dependencies(ref=None, *, transitive=False, filters=None) читают метаданные снимка,
Graph.edges содержит связи. Catalog.publish(graph) использует захваченный локальный
снимок и точные requirements без повторного graph info.
